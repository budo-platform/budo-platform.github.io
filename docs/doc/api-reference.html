API Reference #

This page is a compact map of the public developer surface. The generated budo-llm.md file in the repository is the exhaustive source for signatures, edge cases, and WebAssembly import lists. Use this page when you want to remember where something lives.

CLI #

Budo Pro: android-apk and android-aab are Budo Pro commands. During Budo's public launch, the released Budo binaries include them for free; a later release will make them a paid feature. JavaScript globals #

JavaScript and TypeScript apps run in QuickJS. Budo injects sys, console, fetch, and subsystem aliases where documented.

The sys tree contains canvas, transform, path, svg, font, graphics, gl, math, input, window, animation, timer, audio, midi, db, file, network, udp, magneto, device, neural, and capabilities.

sys.animation #

sys.animation.requestFrame(callback)
sys.animation.waitForInput(callback, timeoutMs)
sys.animation.cancelFrame(handle)

Register one frame callback. The callback receives a timestamp in milliseconds.

waitForInput registers the callback like requestFrame, but it runs only on the next input event, canvas resize, or after timeoutMs (optional). Until then the last frame stays on screen and Budo stops drawing: desktop builds sleep on window events and Android renders only when needed. End a frame with waitForInput when nothing animates and requestFrame while something moves; an app with sys.gl passes that draw to the screen after the canvas keeps calling requestFrame.

The optional fontSize defaults to 32 for drawing and measurement.

clipRoundRect and clipPath clip with anti-aliased edges; ry defaults to rx. Undo a clip with restore() after save().

saveLayer(alpha = 255, x?, y?, width?, height?, backdropBlur = 0) draws what follows into an offscreen layer that restore() composites back with one opacity (0–255), so overlapping shapes fade as a group. With a rectangle the layer is clipped to it. A backdropBlur above 0 starts the layer with a blurred copy of what is already drawn below it, for frosted-glass panels:

sys.canvas.clipRoundRect(x, y, w, h, 16)

sys.canvas.setFillColor('#FFFFFF99')

sys.canvas.restore()
sys.canvas.restore()

drawRichText(spans, x, y, width, options) and measureRichText(spans, width, options) lay out a paragraph made of spans: strings, or { text, size, color, font } objects (font is a name registered with sys.font.load). Lines grow to their largest span and baselines align; options adds size, the default span size, to the paragraph options.

drawParagraph wraps text to width (0 disables wrapping) at spaces and \n, breaking words that are wider than a line. y is the top of the paragraph, not a baseline. options takes align ('left', 'center', 'right'), lineHeight (a multiple of the font size, default 1.25), and maxLines (the last line ends with an ellipsis). Both functions return { width, height, lines }, so measureParagraph can size a layout before drawing.

Colors accept #RRGGBB, #RRGGBBAA, or numeric ARGB.

Gradients replace the paint color for fills, strokes, and text:

sys.files is the canonical virtual filesystem. Except for a root list(), its paths start with assets/ or files/. sys.assets accepts bundle-relative paths, prepends assets/, exposes no write methods, and shares getError() state with sys.files. Therefore sys.assets.readText('config.json') is equivalent to sys.files.readText('assets/config.json'), while sys.assets.list() is equivalent to sys.files.list('assets'). JS pickText(callback, extension?) opens the platform system picker and returns whether it launched; an extension such as .json filters the picker and is enforced on the selected display name. The callback receives ({name,text}, null) or (null, error), and reads at most 8 MiB. saveText(name, text, callback) opens the platform Save As flow and reports null on success or an error string. Both APIs access locations outside Budo's mounts only through explicit user consent.

Network access is disabled until app.json declares a network policy.

getClipboardText() returns null when the clipboard holds no text. Browsers only read the clipboard asynchronously, so on the web it returns the last text copied, cut, or pasted on the page.

haptic(kind) plays light (default), medium, heavy, selection, success, warning, or error feedback; it returns false on devices without haptics (desktop).

sys.accessibility #

sys.accessibility.isAvailable()
sys.accessibility.isActive()
sys.accessibility.update(nodes)
sys.accessibility.takeActions()

Budo draws everything itself, so screen readers only know what the app tells them. Publish a flat list of nodes in reading order whenever the UI changes:

sys.accessibility.update([
  { id: 'save', role: 'button', label: 'Save', x, y, width, height },
  { id: 'dark', role: 'switch', label: 'Dark mode', checked: true, x, y, width, height },
  { id: 'level', role: 'slider', label: 'Volume', min: 0, max: 100, rangeValue: 40, value: '40%', x, y, width, height },
])
for (const { id, action, value } of sys.accessibility.takeActions()) {
  // action: 'press', 'focus', 'increment', 'decrement', or 'setValue' (with value)
}

Roles: button, checkbox, radio, switch, slider, textbox, list, listitem, heading, text, combobox, option, tab, image, group, link. Bounds are physical canvas pixels. On the web the nodes become invisible ARIA elements over the canvas; on Android they are exposed to TalkBack; on macOS to VoiceOver. Windows and Linux report isAvailable() === false for now. BUDO_ACCESSIBILITY=1 forces isActive() on macOS, for checking a tree with Accessibility Inspector.

isActive() tells whether a screen reader probably runs (always true on the web, where browsers do not tell), so apps can skip building the tree.

Lua reference #

Lua uses the same sys namespace names for canvas, paint, transform, path, SVG, font, GL, input, window, animation, audio, MIDI, SQLite, files/assets, network, UDP, sensors, device, neural, math, and capabilities.

Differences are language-shaped. Lists are 1-based. fetch is callback-based. readBinary returns a Lua string. Neural tensors are Lua tables. sys.timer is JavaScript-only.

end

WebAssembly reference #

WebAssembly imports host functions from env. Names use snake case: canvas_clear, canvas_set_fill_color, transform_translate, path_create, gl_create_program, audio_create_oscillator, db_open, files_read_text, udp_bind, midi_open_input, magneto_get_accel, device_keep_screen_on, neural_load_model, and so on. File import paths start with assets/ or files/. WebAssembly has no sys namespace, so sys.assets does not add a separate import family; use env.files_* with an assets/ path.

String-backed imports take pointer and length pairs. Tensor and pixel APIs copy through exported linear memory. Optional features should be guarded with capability imports or compiled into target-specific modules.

For the complete import list, generate or open budo-llm.md from the same Budo build you ship.
