Native C application contract #

Native C support provides the public lifecycle and core canvas contracts, reusable desktop launcher, constrained project manifest, budo compile, versioned desktop SDK resolution, Android packaging/lifecycle integration, and native GPU shader, texture, buffer, and mesh resources.

Native C applications are trusted, ahead-of-time compiled programs. They run in the Budo process without a sandbox and can access or corrupt host state. Do not compile or run untrusted native projects.

Public headers #

| Header | Public surface | |---|---| | budo/budo.h | Umbrella include for the complete supported native API. | | budo/application.h | BudoApplication, lifecycle callbacks, descriptor discovery, frame and surface snapshots. | | budo/core.h | BudoHost, status/error values, identity, logging, and host error reporting. | | budo/input.h | Borrowed read-only input, pointer, touch, focus, modifiers, and USB-HID key constants. | | budo/graphics.h | Canvas, paint, path, GPU resource handles, capabilities, draw state, and explicit destruction. | | budo/version.h | SDK version, native API version, and build-identity macros. |

Every public struct with struct_size must initialize that field before use. Opaque handles are host-specific and cannot be mixed between hosts or retained across context generations. Functions returning BudoStatus use BUDO_STATUS_OK as their sole success value; detailed synchronous failures are copied to budo_host_last_error().

Descriptor discovery #

Include <budo/budo.h> and define exactly one budo_get_application() function. Do not define main(); the Budo launcher owns the process entry point, platform initialization, event loop, presentation, and shutdown.

The returned BudoApplication descriptor must remain valid for the application lifetime. Set struct_size, api_version, sdk_version, and sdk_build_id from the SDK macros. initialize and frame are required. All other callbacks are optional.

The host rejects descriptors whose API version, SDK version, or SDK build identity differs from the host. Cross-version source or ABI compatibility is not currently promised; rebuild the application with the selected SDK.

Lifecycle #

Callbacks are synchronous and run on the platform/render thread:

  1. initialize creates application state after host services are ready.
  2. surface_created reports that graphics use is legal.
  3. resize supplies physical dimensions and display density.
  4. frame supplies timing, surface information, a zero-based frame index, and read-only input.
  5. pause and resume surround platform suspension.
  6. context_lost invalidates application-owned graphics resources before the surface disappears.
  7. shutdown releases application-owned state exactly once.

Frames are suppressed until initialization and surface creation succeed, while paused, and after context loss. A recreated surface produces another surface_created and resize sequence. If initialize fails after creating partial state, shutdown still runs once with that state.

Missing optional callbacks mean that no application work is required for that event. There is no public destroy callback: shutdown is the application's only state-release operation.

Ownership and lifetime #

The application owns the value stored through app_state and releases it during shutdown. Host, frame, surface, input, error, and identity pointers are borrowed. Do not retain callback-local pointers after a callback returns. Descriptor strings must remain valid for the complete application lifetime.

Graphics APIs are legal only inside surface_created, resize, frame, and context_lost while the current surface is active. Presentation and buffer swapping remain host-owned. Application worker threads must be stopped before shutdown returns.

budo_host_canvas() returns a callback-scoped borrowed BudoCanvas. Paints and paths created through budo_paint_create() and budo_path_create() are application-owned and must be destroyed explicitly. Destroy surface resources before context_lost returns and recreate them during the next surface_created; handles cannot cross surface generations.

The core canvas supports clear, rectangles, rounded rectangles, circles, ovals, lines, points, paths, save/restore, translation, scale, rotation, and rectangular clipping. Colors are 32-bit ARGB values created with BUDO_COLOR_ARGB() or BUDO_COLOR_RGB(). Paint configuration covers fill and stroke styles, width, anti-aliasing, caps, joins, color, and alpha. Operations return BUDO_STATUS_INVALID_STATE when used outside an active graphics callback. The host owns flushing and presentation.

GPU shaders, textures, buffers, and meshes #

Desktop and Android native C applications expose the same initial GPU resource surface. Call budo_host_graphics_capabilities() during initialize to query its versioned feature flags and limits. GPU resources themselves are legal only inside graphics callbacks on the render thread. They belong to one host and one surface generation and must be destroyed before context_lost returns.

The surface includes in-memory and project-relative file-backed GLSL ES 3.00 vertex/fragment programs, scalar/vector and 4x4 matrix uniforms, vertex and 16-bit index buffers, RGBA8 2D textures, encoded image textures loaded from project-relative files or borrowed memory, vertex layouts, and indexed or non-indexed screen mesh draws. Vertex attributes support 32-bit floats and normalized unsigned bytes. Draw state supports triangle/line/point primitives, depth test/write, front/back culling, and none/alpha/additive/premultiplied-alpha blending. The host still owns the framebuffer, viewport, flushing, and presentation. Texture unit zero is reserved for host canvas composition; application textures use units 1 through 7.

Application-owned RGBA8 render targets support explicit fullscreen processing without exposing framebuffer or texture identifiers. Create and resize them in graphics callbacks, query their dimensions, and destroy them before context_lost returns. budo_canvas_draw_fullscreen_pass() accepts explicit borrowed endpoints: a null source samples the current host canvas, and a null destination draws to the screen. A non-null source is exposed as u_canvas on reserved texture unit zero; u_resolution is the destination size. The host flushes the canvas only when it is the source, selects the complete destination viewport, and restores backend state after the synchronous call. Sampling from and drawing to the same target is rejected to avoid an undefined GPU feedback loop. A pass does not retain either target or the shader program.

budo_canvas_draw_region_pass() uses the same borrowed endpoints but draws into an integer rectangle measured in physical destination pixels from the top-left. Width and height must be positive. Signed origins allow intentional partial placement outside the destination; the host clips the half-open requested rectangle to the destination. A completely clipped rectangle succeeds without drawing. Partial clipping crops the source mapping instead of stretching it, so the complete source still maps over the original requested rectangle. u_resolution remains the complete destination size and u_offset receives the requested top-left origin. Screen pixels outside the clipped rectangle are preserved, and the host restores the caller's framebuffer and viewport after the call.

All operations are synchronous. Invalid arguments return BUDO_STATUS_INVALID_ARGUMENT; wrong thread, callback, generation, or resource destruction order returns BUDO_STATUS_INVALID_STATE; shader compile/link and draw failures return BUDO_STATUS_APPLICATION_ERROR. The detailed backend message is copied into budo_host_last_error(). A live mesh retains its vertex and index buffers, so destroy meshes before buffers. A typical destruction order is mesh, texture, buffers, then shader program.

Shader and image paths are UTF-8 paths relative to the native project and must be declared in the manifest's assets list. Absolute paths and . / .. segments are rejected. Encoded image bytes are borrowed only for the synchronous constructor call and decode top-down to RGBA8. Supported decoder formats include PNG, JPEG, BMP, GIF, TGA, PSD, HDR, PIC, and PNM. Use budo_texture_2d_get_size() to query decoded dimensions. File open, image decode, and shader compile/link failures return BUDO_STATUS_APPLICATION_ERROR and preserve the backend diagnostic in budo_host_last_error().

Depth render targets, cubemaps, instancing, and GPU-backed canvas textures are not yet part of the public native C API.

Status, errors, and logging #

BUDO_STATUS_OK is the only success status. initialize returns a BudoStatus; on failure it should also call budo_host_set_error() with a useful UTF-8 message. The host copies that message. budo_host_last_error() returns a borrowed error valid until the next mutation or shutdown.

budo_host_log() accepts a complete UTF-8 message and a BudoLogLevel. The initial contract intentionally avoids cross-boundary variadic functions and allocation APIs.

Frame, surface, and input #

BudoSurfaceInfo contains physical pixel width and height plus display density. BudoFrameInfo contains timestamp milliseconds, delta seconds, a zero-based frame index, a copied surface snapshot, and a borrowed BudoInput handle.

Input queries copy pointer and touch values into caller-owned structures. Keyboard values use platform-independent USB HID usage IDs declared as BUDO_KEY_*; no SDL type is exposed. Input handles are read-only and callback-scoped.

Current example #

The canvas example under examples/12_native_c demonstrates descriptor discovery, application-owned state, logging, frame timing, resize handling, pointer/touch and keyboard input, canvas drawing, and context-loss-safe paint ownership without a user main(). Build it with budo compile examples/12_native_c and optionally add --run.

The GPU example under examples/13_native_gpu renders a rotating indexed, textured quad. It demonstrates capability discovery, embedded shaders, uniforms, buffers, RGBA8 textures, mesh draw state, and resource recreation after context loss.

The asset-backed GPU example under examples/14_native_gpu_assets loads its vertex and fragment shaders from staged project assets and decodes an embedded PNG into a texture. It demonstrates the asset-path and encoded-image APIs on desktop and Android.

The render-target example under examples/15_native_render_targets draws asymmetric canvas content, runs canvas → target A → target B → screen at half resolution, resizes both targets with the surface, and recreates all resources after context loss.

The region-pass example under examples/17_native_region_passes captures the canvas into a target and draws it into negative-origin and edge-overflow screen rectangles, demonstrating top-left bounds, clipping without stretching, destination uniforms, and context-loss-safe ownership.
