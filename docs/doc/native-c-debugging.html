Native C debugging #

Native C applications run as trusted, unsandboxed code in the Budo host process. A crash, deadlock, or memory error can terminate or corrupt the host.

Desktop symbols and compilation database #

Use budo compile my-app --debug for the clearest source-level debugging, or the default RelWithDebInfo build for optimized code with symbols. The command prints the executable path; by default it is .budo/native/build/bin/<application>. The compilation database is generated at .budo/native/build/compile_commands.json, and the C starter configures VS Code to use it.

Set breakpoints in budo_get_application(), initialize, surface_created, frame, context_lost, and shutdown. Launch the produced executable with LLDB on macOS, GDB on Linux, or the Visual Studio C++ debugger on Windows. The application does not define main(); stepping through startup first enters the Budo launcher before descriptor discovery.

Sanitizers #

Clang and GCC builds can instrument application sources:

Terminal
budo compile my-app --debug --sanitize address,undefined --run

AddressSanitizer catches many invalid accesses and lifetime bugs; UBSan catches selected undefined behavior. Budo, Skia, SDL, and other prebuilt SDK libraries are not instrumented by this switch. Sanitizers are intentionally unavailable with --release and unsupported compiler families.

Android #

Build a debug APK, open the staged Android project in Android Studio, select the native debugger, and place breakpoints in the same descriptor and lifecycle callbacks. Native debug packages retain symbols and route host/application logs to logcat. Public callbacks and graphics run on the GLSurfaceView render thread, not the Android UI thread. Exercise pause/resume and surface recreation when debugging graphics resources; destroy generation-bound handles from context_lost and recreate them from surface_created.

Build and ABI diagnostics #

Inspect .budo/native/budo-native-build.json for the selected SDK, target tuple, compiler, configuration, sanitizers, component digests, cache status, and executable. Use budo cache native inspect and budo cache sdk inspect when diagnosing stale or missing artifacts. An SDK built for another operating system, architecture, or compiler family cannot be reused; select the matching SDK and recompile.
